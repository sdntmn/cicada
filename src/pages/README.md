# Слой `pages`

## Назначение

Содержит страницы приложения — верхнеуровневые компоненты, соответствующих маршрутам (URL). Каждая страница собирает фичи, виджеты и сущности в законченный пользовательский интерфейс.

## Структура

Каждая страница имеет следующую структуру:

```
pages/
  <PageName>/
    index.ts          # Публичный API (экспорт компонента страницы)
    ui/               # UI-компоненты, специфичные для страницы
      <ComponentName>/
        Component.tsx
        styles.scss
    lib/              # Логика, специфичная для страницы
      config/         # Конфигурации (таблицы, колонки)
      constants/      # Константы
      helpers/        # Вспомогательные функции
      hooks/          # Кастомные хуки
      types/          # Типы TypeScript
```

## Правила

- Страницы могут зависеть от `widgets`, `features`, `entities`, `shared`.
- Страницы не должны содержать бизнес-логику — она выносится в `features` или `entities`.
- Страницы не должны импортировать друг друга напрямую (навигация осуществляется через маршрутизатор).
- Если компонент используется только на одной странице, но не является переиспользуемым, его можно разместить в `ui/` страницы.
- Избегайте дублирования кода между страницами — общую логику выносите в `shared` или `features`.

## Примеры страниц

- `PreparationAnalysis` — страница подготовки анализа
- `PreparationClaim` — страница подготовки искового заявления
- `Selection` — страница отбора
